## Erkenntnisse

- **Static-Singleton-Anti-Pattern in `ApiQueries`**: alle Query-Objekte sind shared mutable state. Filter aus vorherigen Aufrufen lecken in nachfolgende GET-URLs. Architektur-Root-Cause für Bug 2 und Concurrency-Falle bei parallelen MCP-Aufrufen. Behoben in US-0062 / PR #103 — `ApiQueries.cs` komplett gelöscht.
- **Filter-Naming-Konvention**: easyVerein-API folgt Django-Style (`<feld>__in`, `<feld>__gt`, `<feld>__lt`). Unbekannte Filter werden **still verworfen**, kein HTTP 400. Daher Bug 3 schwer zu entdecken außer durch Beobachtung.
- **Bug 1 Triage-Methode**: Live-Probe gegen echte API über kurzes Konsolen-Programm (Direktreferenz auf Infrastructure-DLLs) ist schneller als MCP-Roundtrip + reproduziert in Sekunden. Hat Hypothese (Reference-Converter) widerlegt — Iron Law gilt, kein Blind-Fix.
- **Tool-Response-Größe**: `list_invoice_items` liefert `WriteIndented`-JSON ≈ 302 KB / 75K Tokens. Bei künftigen Listing-Tools optionalen `limit`-Parameter erwägen.
- **Subagent-Driven Development (US-0062)**: Plan mit 14 Tasks, Implementer + Spec-Reviewer + Code-Reviewer pro Task. Vorteile: konsistentes Pattern über alle 12 Endpoints, jede Abweichung sofort erkannt (Task 9: `static =>` statt `const =` wurde von Spec-Review gefangen). Nachteile: hoher Dispatch-Overhead (~35 Subagent-Calls für triviale mechanische Refactors). Pattern-Vorlage: Combined Spec+Code-Review in einem Subagent (ab Task 5) hat ~2× beschleunigt ohne Qualitätsverlust.
- **Branch-Discipline-Verstoß früh entdeckt**: PR #101 first attempt enthielt durch `git add -A` versehentlich alle untrackten `.claude/`-Skill-Files. Korrektur via `git reset --soft HEAD~1` + explizitem Stage. Subagent-Briefings für US-0062 enthielten explizite Warnung — keine Wiederholung.
- **Pre-existing Bug entdeckt während Refactor**: Code-Reviewer in Task 3 fand `ContactDetailsQuery.ToString()` Zeile 101 (`familyName=` statt `name=`). Out-of-scope für US-0062, separat als Task #15 (Folge-PR) getrackt — Branch-Discipline respektiert.
