## Erkenntnisse

- **Kostenstelle ist kein Buchungsfeld**: KS (`costCentre`) liegt ausschließlich auf der Belegposition (invoice-item), nicht auf der Buchung. `update_booking` kann nur `sphere`, `billingAccountId`, `bookingProjectId`. Vollständige Kategorisierung = Buchung (Projekt/Sphäre/Konto) **und** Position (Konto/Sphäre/KS) parallel pflegen.
- **KS nicht API-filterbar**: „Buchungen ohne KS" erfordert Vollscan aller Buchungen + Belegpositionen, kein Query-Filter.
- **Buchungskonto-ID ≠ SKR42-Nummer**: `update_booking`/`update_invoice_item` brauchen die billing-account-**ID**; SKR42-Nummer (z. B. 42900) erst per `list_billing_accounts(numberGte/Lte)` auf ID auflösen. Konto 40500 existiert doppelt (ID 58237 mit 8 Buchungen vs. 128505 defaultSphere 1, 0 Buchungen) — Präzedenz-ID 58237 verwendet.
- **CLAUDE.md ≠ Issue-Status**: Mehrere implementierte Endpoints (US-0011, US-0015, US-0016) haben noch offene Issues. CLAUDE.md-„implementiert" stets gegen Code verifizieren, bevor Issue geschlossen wird.
- **Vorsteuer steuert Wareneingangs-Konto**: 52000 (Wareneingang, kein VSt) vs. 54000/54180 (19 % Vorsteuer). Position-`taxRate` prüfen, nicht pauschal 52000 setzen.
