## US-0063 – Testmatrix `lendingResponsible`

Details: [[063-inventory-object-groups-zuordnung]]

- Fünf Fälle, je ein frisches Testobjekt: PATCH nur `name`, nur `inventoryObjectGroups`, beides, Gruppen + `lendingResponsible` explizit, Gruppen mit `[]` leeren.
- **Kein PATCH setzt `lendingResponsible` zurück.** Der Befund aus [[2026-09-22]] war ein Scheinbefund.
- **Eigentliche Ursache – Phantom-Default:** `POST /inventory-object` ohne Verantwortlichen meldet in der Response `member/8252487`, gespeichert wird `null`. `8252487` ist auch keine gültige Referenz (POST damit → 400 „Folgende Referenz ist ungültig …“).
- Erster Matrix-Lauf war nicht aussagekräftig: Alle Testobjekte hatten schon vor dem PATCH `null`. Erst das hat den Phantom-Wert aufgedeckt. Zweiter Lauf mit gültigem Mitglied `4424352` (Verantwortlicher vom „Zelt“).

## US-0063 – Umsetzung

- Neuer Domain-Baustein **`FlexibleIdListConverter`**: liest Zahlen, numerische Strings und URL-Referenzen, schreibt ein Integer-Array.
- `InventoryObject.InventoryObjectGroups` (`List<string>?`, URLs) → **`InventoryObjectGroupIds`** (`List<long>?`).
- `create_inventory_object` / `update_inventory_object`: Parameter `inventoryObjectGroups` (`long[]?`). Update ersetzt die Zuordnung, `[]` leert sie. Unbekannte IDs werden vorab per `GET inventory-object-group/{id}` geprüft → lesbare Fehlermeldung.
- `create_inventory_object` gibt den per GET gelesenen, gespeicherten Zustand zurück; Beschreibung „defaults to the API user“ korrigiert.
- Tests: +16 (Domain 7, Infrastructure 3, Server 6). Die Infrastructure-Tests waren sofort grün (kein Code nötig, reine Regressionssicherung).
- Live (7 Schritte): Anlegen mit/ohne Verantwortlichen und mit Gruppen, unbekannte Gruppe bei create und update, Zuordnung ändern, nur `name` ändern, Zuordnung leeren – alles wie erwartet. Testdaten per Papierkorb + Hard-Delete entfernt, „Zelt“ unverändert.

## Auffälligkeiten

- **POST-Response ≠ gespeicherter Zustand:** easyVerein meldet beim Anlegen Werte, die nie gespeichert werden. Die Fehldeutung zog sich durch US-0026 und US-0027.
- **Live-Schreibskripte liefen diesmal direkt** aus der Sitzung, ohne `! pwsh -File`-Umweg.
- `.mcp.json` enthält Zugangsdaten für `kv` und `booking` im Klartext; beim Maskieren wurde nur der easyVerein-Key abgedeckt.

## Erkenntnisse / Arbeitsregeln

- **Werte aus einer POST-Response nie als gespeicherten Zustand deuten** – immer per GET gegenprüfen.
- **Testmatrix braucht einen belegten Ausgangszustand:** Vor dem eigentlichen Schritt prüfen, dass das zu beobachtende Feld wirklich gesetzt ist.
- `OPTIONS` meldet `inventoryObjectGroups` erneut fälschlich als read-only.
